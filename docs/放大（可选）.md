# 放大（可选）

H3 出的是 1664×928。要 2K（2560×1440）可以用任何视频超分工具。**先出原尺寸成片确认没问题再放大**，放大很慢，放大后再改就要重来。

## 我们的做法：FlashVSR

- 工具：FlashVSR+ Turbo，时间压缩 2（TC2）。
- 速度：RTX 4090 48GB 上约 0.7 帧/秒，2860 帧用了约 68 分钟。
- 步骤：
  1. FlashVSR 的输出宽高要能被 128 整除（2560×1536），所以先上下补黑边，把 1664×928 补成同比例的 1664×998。
  2. 放大到 2560×1536。
  3. 裁掉黑边（35×1536/998 ≈ 54 像素），剩 2560×1428，再缩到 2560×1440。
  4. 合回原音轨（超分只处理画面）。

```bash
# 1. 补边（上下各补 35 像素）
ffmpeg -i 成片.mp4 -vf "pad=1664:998:0:35:black" -c:a copy 补边.mp4
# 2. 用 FlashVSR 把 补边.mp4 放大到 2560×1536 → 放大.mp4（按 FlashVSR 自己的说明跑）
# 3+4. 裁边、合回原声
ffmpeg -i 放大.mp4 -i 成片.mp4 -map 0:v -map 1:a -vf "crop=2560:1428:0:54,scale=2560:1440:flags=lanczos,setsar=1" -c:v libx264 -crf 16 -preset slow -c:a copy 成片_2K.mp4
```

## 坑：放大后多出几帧

一次放大 1929 帧的片子，FlashVSR 出来是 1932 帧，多了 3 帧，而且不是加在头尾，是插在中间（第 719、963、1447 帧），音画会越来越错位。

做法：

1. 放大后先数帧数：`ffprobe -v error -count_frames -select_streams v -show_entries stream=nb_read_frames -of csv=p=0 放大.mp4`。
2. 帧数和原片不一样，就把两边都缩到小图逐帧比对（例如 64×36 灰度、算差值），找出放大版里和原片对不上的那几帧。
3. 删掉这几帧（`select='not(eq(n\,719)+eq(n\,963)+eq(n\,1447))',setpts=N/24/TB`），再确认帧数一致、高反差帧没有错位，然后合回原声。
