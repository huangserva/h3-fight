# 工作流怎么搭

仓库不带工作流文件，这里写清楚怎么搭。我们的工作流是在 BUNNY 作者（JOKER141 / FourBunny）公开的 SelfLift 工作流基础上改的，作者的原版可以去作者主页找。

搭好后在 ComfyUI 里用 **导出（API）**（Export (API)）存成：

- `库/模板/三参考图.json`：有参考图（人物、场景、对手），`出片.py --参考图 …` 用它；
- `库/模板/无参考图.json`：只靠提示词，不带 `--参考图` 时用它。

`出片.py` 不认节点编号，按作用找节点：有 `prompt` 和 `clip` 输入的是条件节点，有 `seed` 的是采样节点，有 `filename_prefix` 的是保存节点，接在条件节点 `ref_images` 上的 `LoadImage` 是参考图。所以节点编号随意，只要每种节点各一个。参考图可以先接 1 张，`出片.py` 会按 `--参考图` 的张数自动补到最多 9 张；首帧引导（`MiniMaxH3AddGuide`）也是它自动加的，不用搭。

搭完跑 `python3 工具/自检.py`，它会核对节点和模型文件。

## 节点和连线（三参考图版）

模型这一路（从上往下串）：

| # | 节点 | 设置 | 输入接谁 |
|---|---|---|---|
| A | `UNETLoader` | `minimax_h3_hybrid_fl2va_ref2va_b25-49-int8.safetensors`，weight_dtype default | — |
| B | `LoraLoaderBypassModelOnly` | `minimax_h3_turbo_v4_step600_ema_pruned_comfyui.safetensors`，强度 0.7 | model ← A |
| C | `SelfLiftAvatarH3TST` | tau 0.2 | model ← B |
| D | `LoraLoaderModelOnly` | `H3_Fight_Flow_V1.safetensors`，0.65 | model ← C |
| E | `LoraLoaderModelOnly` | `H3_Combat_V2.safetensors`，0.5 | model ← D |
| F | `LoraLoaderModelOnly` | `Motion_Repair.safetensors`，0.25 | model ← E |

编码器和 VAE：

| # | 节点 | 设置 |
|---|---|---|
| G | `CLIPLoader` | `qwen3vl_32b_minimax_h3_int8_convrot.safetensors`，type `minimax` |
| H | `VAELoader` | `minimax_h3_video_vae_fp16.safetensors`（视频） |
| I | `VAELoader` | `minimax_h3_audio_vae_fp32.safetensors`（音频） |
| J | `ResolutionSelector` | 16:9 (Widescreen)，megapixels 1.5，multiple 32（得到 1664×928） |

条件、采样、输出：

| # | 节点 | 设置 | 输入接谁 |
|---|---|---|---|
| K | `LoadImage` ×3 | 人物、场景、对手（文件名随便，出片时会换） | — |
| L | `MiniMaxH3ReferenceToVideo` | length 243，ref_image_size match，prompt 留空 | clip ← G，vae ← H，audio_vae ← I，width/height ← J，ref_image_0/1/2 ← K 三张（顺序：人物、场景、对手） |
| M | `ConditioningZeroOut` | — | conditioning ← L 的条件输出 |
| N | `KSamplerSelect` | euler | — |
| O | `BasicScheduler` | simple，8 步，denoise 1.0 | model ← F |
| P | `H3SigmaRefiner` | extra_steps 1，start_at_sigma 0.7，end_at_sigma 0.0，spacing cosine | sigmas ← O |
| Q | `SelfLiftAvatarH3Sampler` | seed 1，cfg 1.0，transition_step 6，lowres_scale 0.5，rho 0.0，w_min 0.5，w_max 1.0，upscaler_model `minimax_h3_latent_upscaler_3d_conv_v1_fp16.safetensors`，highres_tiling 关 | low_res_model ← F，positive ← L 条件，negative ← M，vae ← H，latent_image ← L 的 latent 输出，sampler ← N，sigmas ← P |
| R | `MiniMaxH3AVDecodeT8` | — | av_latent ← Q，video_vae ← H，audio_vae ← I |
| S | `CreateVideo` | fps 24 | images ← R 画面，audio ← R 声音 |
| T | `SaveVideo` | mp4，h264，filename_prefix 随意（出片时会换） | video ← S |

## 无参考图版

和上面一样，只是：

- 不要 K（三个 `LoadImage`）；
- L 换成 `MiniMaxH3AudioConditioningT8`：length 243，task_type auto，audio_mode native，audio_denoise_strength 1.0，add_source_as_reference 关，strict_prompt_tags 开，ref_image_size match；输入 clip ← G，video_vae ← H，audio_vae ← I，width/height ← J。

## 注意

- 模型文件名和你下载的一致就行，不必和上表一字不差；`自检.py` 会按你的工作流核对 ComfyUI 认不认得这些文件。
- 部件和参数是出过好片的那一套。换写法时不要同时换部件，否则分不清是哪一项起的作用。
